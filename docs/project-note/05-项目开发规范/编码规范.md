# 编码规范

权威来源：`AGENTS.md`（边界与状态规则）+ `apps/docs/content/docs/developers/conventions.mdx`（命名/i18n）。本页只做索引与高频要点的浓缩，**冲突时以上述两份为准**。

## 命名（`conventions.mdx` §1）

| 对象 | 规则 | 例 |
|---|---|---|
| 文件 | `kebab-case.ts(x)` | `agent-row-actions.tsx` |
| 组件 | `PascalCase` | `AgentRowActions` |
| Hook | `useCamelCase` | `useWorkspaceId` |
| 测试 | 同目录 `<file>.test.ts(x)` | `button.test.tsx` |
| Store | `<feature>-store.ts` 导出 `use<Feature>Store` | `useIssueDraftStore` |
| TS 类型 | `PascalCase`，禁止 `IPrefix` / `_t` 后缀 | `Issue`、`AgentRuntime` |
| 枚举 | 优先字符串字面量联合 | `type IssuePriority = "urgent" \| ...` |
| Query key | `<feature>/queries.ts` 里的工厂 | `issueKeys.detail(id)` |

数据库与 Go 命名见 `conventions.mdx`（表名单数、列 `snake_case`、迁移 `NNN_name.up/down.sql` 双份）。

路由命名：工作区前路由用单词或 `/{noun}/{verb}`（`/login`、`/workspaces/new`），**禁止连字符根路径**——会与工作区 slug 冲突并需要无限扩充预留词表。新增保留 slug 要改 `server/internal/handler/reserved_slugs.json` 并跑 `pnpm generate:reserved-slugs`。

## 注释

- **代码注释一律英文**。发现中文注释视为 bug（`conventions.mdx`）。
- 注释只写非显然的原因与约束（为什么这样、不能怎样），不写"这里做了什么"。
- 过期计划、事故叙事在改动时删除；保留工具指令与混合版本契约。

## 提交信息

Conventional commits，原子提交按意图分组：`feat(scope)`、`fix(scope)`、`refactor(scope)`、`docs`、`test(scope)`、`chore(scope)`。

## 包边界（ESLint 强制，不是文档约定）

| 包 | 禁止 | 规则位置 |
|---|---|---|
| `packages/core` | `react-dom`、`@multica/ui`、`@multica/views`、`@base-ui/react`、`@radix-ui`、`next/*`、`process.env`、直接 `localStorage`/`sessionStorage` | `packages/core/eslint.config.mjs:9-50` |
| `packages/views` | `zustand` 的 `create`/`createStore`；JSX 裸文本（必须过 `useT`）；整页跳转；图标库直连 | `packages/views/eslint.config.mjs:19-58` |
| `packages/ui` | `@multica/core`（依赖表 + `import-x/no-extraneous-dependencies`） | `packages/ui/package.json:36-67`、`packages/eslint-config/base.js:49` |
| `apps/mobile` | core 的非纯 barrel（只允许 `./types`、`./markdown`）；`@react-navigation/*` 直连 | `apps/mobile/eslint.config.js:9-38` |
| Desktop 应用层 | 具名导入 `useNavigate`/`Navigate`、调用 `router.navigate`（`platform/**` 豁免） | `apps/desktop/eslint.config.mjs:53-82` |

> 注意：`packages/views` **没有**禁止 `next/*` / `react-router-dom` 的 lint 规则——只有 AGENTS.md 约定与桌面 MUL-4741 规则兜底。越界 import 在 web 端通常不报错，到 desktop 打包才炸。

## UI 规则（`AGENTS.md` + `packages/ui/docs/`）

- 动作按钮用 `Button`，目标跳转用链接（`packages/ui/docs/button.md`）。
- `Button` **没有** `loading` prop：pending 用 spinner + `disabled` + `aria-busy` 组合。
- 变体只用声明的语义变体（`default/outline/secondary/ghost/brand/brandSubtle/destructive/link`），不要覆盖几何或颜色。
- 圆角：按钮/链接/可点 chip 是圆角矩形，尺寸自带半径；`rounded-full` **仅**用于头像、状态点、计数、开关、单选、滑块、色块、悬浮聊天按钮与发送/停止按钮（lint 拦其他用法）。
- 排版用 `packages/ui/styles/tokens.css` 的 `--text-*` 角色化字阶，不用 Tailwind 默认字号阶。
- 弹窗用 `Dialog`（聚焦任务）、`Popover`（上下文选项）、`AlertDialog`（重大确认）；标题与描述必填；提交中的弹窗只在成功后关闭（`packages/ui/docs/dialog.md`）。
- 图标一律从 `@multica/ui/icons` 导入；缺图标按 `.agents/skills/multica-icons/SKILL.md` 自己画，**禁止内联 SVG 或 emoji 替代**。
- 组件优先用已有 shadcn/Base UI 原语；新增用 `pnpm ui:add <component>`（`@reui/*` 时拒绝覆盖提示，`REUI_LICENSE_KEY` 只放环境变量，不入库）。

## UI 文案

- 描述默认省略；不重复标题、标签、值、状态或按钮动作。
- 只有存在非显然的**选择、约束、后果或下一步**时才写帮助文本。
- 中文术语对照表在 `conventions.mdx` §2：`issue→任务`、`workspace→工作区`、`agent→智能体`、`autopilot→自动化`、`daemon→守护进程`、`runtime→运行时`；角色与状态枚举保持小写英文。

## 状态管理规则（`AGENTS.md` State Rules）

1. 服务端数据 → TanStack Query；客户端 UI 态 → Zustand。
2. 只有 auth/workspace store 可直接调 `api.*`。
3. workspace 作用域的 query key 必须含 `wsId`。
4. Zustand 选择器返回稳定引用；派生对象/数组用 shallow。
5. WS 事件只 patch/invalidate Query 缓存，**不把服务端 payload 存进 Zustand**。
6. 乐观更新必须：可预测结果 + 失败罕见 + 回滚简单 + 不离开当前屏；打补丁前先快照，失败回滚，settle 后失效。
7. 创建/删除/离开必须等服务器响应再导航或清理（例外：workspace leave 的历史债、移动端收件箱标记已读）。

## API 兼容规则

- 已安装的桌面端可能连更新的后端：**响应兼容性是硬约束**。
- UI 消费的 JSON 必须过 zod + `parseWithFallback`，禁止 `as T`。
- 可选字段提供默认值；未知枚举有回退分支；不要只靠一个后端 flag 驱动关键能力。

## 后端专属规则

- UUID：资源参数用 `loadXxxForUser` 解析后用 `entity.ID` 写；纯 UUID 输入用 `parseUUIDOrBadRequest`；可信 round-trip 才用 `parseUUID`。
- workspace 查询必须过滤 `workspace_id`；成员身份由中间件把关。
- 迁移：只加索引用 `CONCURRENTLY` + 单语句文件 + 登记 `cmd/migrate/main.go`。
- 不加 FK / 级联。

## 反模式自检清单

提交前对照 `AGENTS.md` 的"Change and Delivery Rules"：

- [ ] 没有为理论上的并发/安全边界提前加复杂度（有具体失败模式与用户认可才做）
- [ ] 没有新增内部兼容 shim / 双写 / 遗留适配层（API 响应兼容除外）
- [ ] 没有留下 TODO、占位实现或"后续再做"的脚手架
- [ ] 改动是复用既有模式，而非引入第二套约定
- [ ] 文案默认无描述；有描述则说明约束/后果
