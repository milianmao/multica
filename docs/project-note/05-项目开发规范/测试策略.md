# 测试策略

## 分层：每个行为只有一个"权威测试层"

| 层 | 位置 | 测什么 | 不测什么 |
|---|---|---|---|
| Helper 单测 | 与实现同目录 `.test.ts` | 解析、状态矩阵、纯变换 | 组件渲染 |
| 组件测（Vitest + jsdom） | `packages/views/**`、`apps/*` | 接线、可访问性、happy path、命名的回归 | 共享行为（那是 core 的） |
| Go 单测（可带 DB） | `server/internal/**/*_test.go`（1586 个） | 业务规则、SQL 语义、并发/竞态 | 跨服务端到端 |
| E2E（Playwright） | `e2e/*.spec.ts`（46 个） | 用户可见的关键路径 | 内部实现细节 |

规则原话：**"Do not test shared behavior in app suites."** 共享逻辑的测试放 `packages/core`，组件的放 `packages/views`，平台接线的放 `apps/*`。

## 前端

- 框架：Vitest 4 + `@testing-library/react` + jsdom。
- 纯 DOM-free 的 `.test.ts` 首行加 `// @vitest-environment node`；但**如果它会静默把被测代码切到 SSR 路径就不要加**。
- 所有 jsdom 套件统一在 setup 里加载 `@multica/vitest-setup/web-storage`（提供内存版 Storage），**不要各包自己塞 localStorage shim**。
- `packages/views` 的测试**禁止** mock `next/*` 或 `react-router-dom`——mock 它们等于测了个假的平台层。
- mock store 时用 Zustand 的可调用形态 + `getState`；API 在 `@multica/core/api` 这一层 mock。

## 后端（Go）

| 关注点 | 约定 |
|---|---|
| Fixture | `server/internal/testutil`：`dbfx.New(pool, wsID, userID)` + `Insert(table, cols)`，自动按逆序 `t.Cleanup` |
| HTTP 断言 | `testutil.Call(h, req).Want(status).JSON(&out)`；`JSONRequest` 对 `string`/`[]byte`/`io.Reader` 原样透传（便于发畸形请求） |
| 诊断信息 | 产品断言与用例专属诊断写在测试里，**不要塞进 fixture helper** |
| 共享库并发 | 所有 DB 测试共享一个库、包间并行：断言必须锚定**自己的 fixture 行**（如 `pending`/`settled` + 自己的 ID），**不要断言调用总数或结果长度** |
| 真实 agent CLI | 默认测试**禁止**解析/执行用户安装的 agent CLI；必须传测试构造的假路径或不存在路径；新命令登记到 `scripts/agent-cli-command-names.txt` |
| 真实 agent smoke | 需显式授权，加 `agentintegration` tag 且检查 `MULTICA_RUN_REAL_AGENT_SMOKE=1` 才能查可执行文件 |
| 命令 | `make test`（先建库+迁移，再 `scripts/test-go.sh --race`） |

`test-go.sh` 分两段跑：除 `pkg/agent` 外的所有包按默认并行度；`pkg/agent` 用 `-p 2 -parallel 2` 限流（子进程测试有硬 deadline）。

## E2E（Playwright）

- 配置：`playwright.config.ts`——`workers: 1`、`retries: 0`、`timeout: 60s`、单 chromium。
- **不自动起服务**：必须已有后端/前端在跑（`baseURL` 取 `PLAYWRIGHT_BASE_URL` 或 `FRONTEND_ORIGIN`）。
- 环境从 `.env.worktree` 或 `.env` 读取（`e2e/env.ts`）。
- 夹具与工具：`e2e/helpers.ts`（`loginAsDefault`、`createTestApi`、`appRail` 等）、`e2e/fixtures.ts`、`TestApiClient` 负责 setup/teardown。
- 性能场景独立配置（`playwright.perf.config.ts`，单 worker、无重试、需生产构建），被主套件 `testIgnore` 排除。

## 什么该写成永久测试

必须能抓到"合理的消费方可见 bug"：行为、边界、不变量、状态转换、优先级、错误路径。**不要**写：

- 接线/转发/mock 回声/源码文本断言
- 同义反复（"不抛就算过"）
- "非空"/"长度增加"这类弱断言
- 同一路径的重复行

一次性验证用临时脚本，不要留在仓库。**既有测试若只是在钉住文案/实现细节/偶然行为，应删除而不是重新钉住。**

## CI 门禁（`.github/workflows/ci.yml`）

| Job | 触发范围 | 内容 |
|---|---|---|
| `changes` | 总是 | `node --test scripts/ci-scope.test.mjs` 先证明路径选择本身正确，再 `dorny/paths-filter` + `scripts/ci-scope.mjs decide` |
| `sqlc-check` | `sqlc` | `make sqlc` 后校验生成物无 diff、无未跟踪文件 |
| `frontend-build` | `frontend` | build + typecheck + lint |
| `frontend-test` | `frontend` | web/core/desktop 测试 |
| `frontend-views-test` | `frontend` | views 测试分 2 个 shard（wall-clock 优化） |
| `frontend-quality` | `quality_only` | 前端质量门 |
| `backend-tests` / `backend-agent-tests` | `backend` | Go 测试（分 regular / agent 两半，各自 runner） |
| `go-vulnerability-scan` | `backend` | `govulncheck` |
| `backend-darwin-vet` | `backend` | darwin 平台编译与 vet |
| `windows-execenv` | `runtime` | Windows 进程树/Job Object/媒体流/参数传递回归 |
| `macos-runtime`、`macos-processtree` | `runtime`/`processtree` | macOS 专项 |
| `image-budget`、`installer`、`script-checks` | 各自范围 | 镜像体积、安装脚本、shell 脚本测试 |
| 聚合 | — | `backend`、`frontend` 汇总 job |

`scripts/` 与 `.github/` 的改动跑 `pnpm test:scripts` + 对应 `bash scripts/<name>.test.sh`。

## 本地推荐顺序

```
1. pnpm typecheck          # 最快发现契约破坏
2. pnpm test               # 受影响包的 vitest
3. make test               # Go（含 DB）
4. pnpm exec playwright test   # 关键路径（服务需先跑）
5. make check              # 全量（typecheck → TS → Go → E2E）
```

窄检查先跑，风险足够大再放宽；**报告实际跑了什么、跳过了什么**。
