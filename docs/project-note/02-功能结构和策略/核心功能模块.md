# 核心功能模块

## 模块全景（按用户可感知的能力）

```
工作区 Workspace ─┬─ Issue（任务）─┬─ Comment / Activity / Attachment
                  │                ├─ Sub-issue / Duplicate / Wakeup
                  │                └─ Run(task) ── Agent ── Runtime(daemon)
                  ├─ Project ── Project Resource / Private access
                  ├─ Agent ── Skill / MCP server / Env / Builder
                  ├─ Squad（人+agent 混合小队）
                  ├─ Autopilot（定时/webhook 自动化）
                  ├─ Chat（与 agent 的流式会话）
                  ├─ Inbox（通知中心）
                  ├─ Runtime（机器与 CLI 运行环境）
                  ├─ Skill（可复用方法论）
                  ├─ Plugin（第三方 UI 面板/钩子/MCP）
                  └─ Integration（Slack/Lark/WeCom/DingTalk/Telegram/GitHub/VCS）
```

## 前端共享模块（`packages/core`，62 个顶层目录）

| 域 | 目录 | 关键内容 |
|---|---|---|
| 数据访问 | `api/` | `client.ts`（438 个 `async` 方法，6059 行）、`schema.ts`（zod + `parseWithFallback`）、`ws-client.ts` |
| 服务端状态 | 各域的 `queries.ts` | `issueKeys`、`workspaceKeys` 等 key 工厂，全部带 `wsId` |
| 客户端状态 | 57 个 zustand 文件（49 个唯一 `useXxxStore` 导出） | `auth/store`、`chat/store`、`issues/store`、`issues/stores/*`（18 个 UI 态 store）、`navigation/store`、`appearance/*` |
| 实时 | `realtime/` | `provider.tsx`、`use-realtime-sync.ts`（94KB 巨型 updater）、各域 `ws-updaters.ts` |
| 平台抽象 | `platform/` | `StorageAdapter`、workspace storage 单例 |
| 能力子域 | `agents`、`issues`、`projects`、`chat`、`inbox`、`autopilots`、`squads`、`skills`、`runtimes`、`billing`、`plugins`、`search-index`、`vcs`、`connected-apps` | 与后端模块一一对应 |

`packages/views` 是页面实现（1029 个 `.tsx`），`packages/ui` 是原语（70 个组件 + 自绘图标）。

## 三个 app 的职责切分

| app | 独有职责 |
|---|---|
| `apps/web` | Next App Router 路由、SSR/standalone 构建、rewrites（`/api`、`/ws`、`/docs` 反代）、OAuth 回调页 |
| `apps/desktop` | Electron 主进程（daemon 管理、窗口、更新、CDP）、memory router + tab 模型、preload IPC 桥 |
| `apps/mobile` | 独立 UI/数据/hooks/provider/i18n、bearer 认证（不使用浏览器 cookie/CSRF）、Expo 原生构建 |
