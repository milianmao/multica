# 关键设计决策

只记录**有代码或文档证据**、且改动会波及多处的决策。每条给出约束、代价与替代方案。

## D1 · 计算留在用户机器，服务器只做编排

**决策**：agent 进程由用户机器上的 daemon 拉起，用该机器上已安装的 AI CLI 与其自身凭据。服务器不执行模型调用。

**为什么**：代码不出用户环境（README "Their desk is your machine"）。这直接决定了任务必须经过「排队 → 领取 → 本地执行 → 回调」而不是「服务端直接 invoke」。

**代价**：必须有 runtime 在线性、租约、断连宽限、孤儿恢复、跨时区时钟一致性等一整套机制。

**替代方案（被否）**：服务端托管执行——即现在独立的 Qoder Cloud Agents 路径（`MULTICA_VCS_SECRET_KEY` 加密令牌与 journal），作为可选旁路而非主路径。

→ 机制见 [Agent 任务生命周期](../03-核心数据业务流/Agent任务生命周期.md)

## D2 · 单进程单体 + 包边界，而非微服务

**决策**：`cmd/server` 一个进程承载 HTTP、WebSocket、调度器、清理器；划分靠 `internal/*` 包与 handler/service/sqlc 三层。

**为什么**：`AGENTS.md` 规定「不要为理论上的并发或安全边界提前加复杂度」。单体让「评论写入 + 任务入队 + 事件广播」能在**一个事务 + 一次进程内事件分发**里完成。

**代价**：整机维度只能靠副本 + Redis 扩展；后台清扫与请求处理共享同一进程资源。

**替代方案（被否）**：拆服务会让「事务内写业务对象并投递事件」需要 outbox。

## D3 · 无外键、无级联，关系与清理写在应用层

**决策**：不建 FK，不用 `ON DELETE CASCADE`/`CASCADE UPDATE`。

**为什么**：`AGENTS.md` Database Rules —— 删除路径需要业务语义（有的要写墓碑、有的要保留历史），级联会绕过这些逻辑。

**代价**：孤儿行靠后台清扫（`runtime_sweeper.go`、`source_context_sweeper.go`、`environment_log_sweeper.go`）与显式事务补偿；测试必须自己验证清理。

**注意**：39 个迁移里仍含 `REFERENCES`（最晚到 `113_lark_inbound_dedup_per_installation.up.sql`），全属历史遗留；`114` 之后无新增外键。**新迁移不得照抄**。

## D4 · 索引一律 CONCURRENTLY，且每个索引独占一个迁移文件

**决策**：`CREATE [UNIQUE] INDEX CONCURRENTLY`，一条语句一个文件；版本登记进 `server/cmd/migrate/main.go` 的 `concurrentIndexCleanups` / `concurrentDownIndexCleanups`。

**为什么**：迁移执行器把普通迁移放在显式事务里，而 `CONCURRENTLY` 不能在事务中执行；单语句文件让中断后可以安全重跑。

**代价**：迁移数量膨胀（规模见 [部署与运行架构](../01-架构总览/部署与运行架构.md#数据库迁移)）；新增索引要改三处（迁移、登记表、必要时 down 重建）。

## D5 · 数据库访问全部经 sqlc 生成

**决策**：SQL 写在 `server/pkg/db/queries/*.sql`，生成 `server/pkg/db/generated/`，CI 校验无 diff。

**为什么**：让 `workspace_id` 谓词、状态机 `WHERE` 条件这类**安全关键子句**成为可 diff、可被测试守卫的产物，而不是散在字符串拼接里。

**代价**：改一处 SQL 需要 `make sqlc`；handler 不能临时手写查询（`scheduler/db_ops.go` 的 `tryClaim` 是极少数例外，且有专门测试）。

→ 相关守卫测试：[测试策略](../05-项目开发规范/测试策略.md) 的「租户隔离守卫」

## D6 · 实时扇出：本地快路径 + Redis 分片流双写

**决策**：`DualWriteBroadcaster(hub, relay)`；默认 `sharded` 模式，8 个流、FNV-1a 分片、replay grace 5 分钟。

**为什么**：单机时零 Redis 依赖即可工作；多副本时按 scope 分片避免全局流热点；replay grace 让 Pod 重启期间的事件可补齐。

**代价**：**下游必须幂等**（重放窗口内会重复投递）；WeCom 的 claim TTL 必须长于 replay grace，否则重发已读回复。

**替代方案（存在）**：`dual`（sharded + legacy 镜像，用于迁移期）、`legacy`（每 scope 一条流，已不推荐）。

→ 机制见 [实时事件广播链路](../03-核心数据业务流/实时事件广播链路.md)

## D7 · 统一准入契约，禁止静默 no-op

**决策**：所有同步入队入口返回 `queued|coalesced|deferred|steered|blocked + reason_code`。

**为什么**：`admission.go:13-18` 记录了两个事故教训——「评论保存了但 agent 没被触发」曾是不可见的部分失败；拒绝原因曾泄漏私有 agent 是否存在。

**代价**：每个新触发源都必须接入契约并自证在 21 个 reason code 里选了正确的那个；新增触发源最容易漏的是 `origin` 标签（Triage 守卫只对 `OriginNamed` 放行）。

## D8 · WeCom 出站必须单副本（尚未消除的架构约束）

**决策**：WeCom 智能机器人只有「持有该 installation WS 连接的副本」能送达；其它副本靠 Redis relay 转发 + claim 去重。

**为什么**：WeCom 没有 REST 出站接口，`Channel.Send` 直接返回 `ErrSendNotSupported`。

**代价**：`.env.example` 明确要求 `MULTICA_WECOM_*` 启用时后端跑**单副本**；无 Redis 时跨副本回复被丢弃（计 `no_live_connection`）。这是有意的现状而非缺陷，跨副本出站路由尚未落地。

## D9 · 前端：workspace 身份由路由驱动，不用 Context 存服务端状态

**决策**：workspace 身份来自 URL 的 `[workspaceSlug]`；平台镜像只用于请求头、存储命名空间、重连。React Context 仅做平台管道。

**为什么**：避免「同一份 workspace 数据在 Context 和 Query 缓存里各存一份」这种经典双源问题。

**代价**：深链/切工作区必须走 `switchWorkspace(slug, path)` 适配器流程；桌面 tab 模型与路由强耦合（`tab-coordinator.ts:19-21` 规定只有 Coordinator 能写 router）。

## D10 · 客户端新鲜度押在 WebSocket 上

**决策**：Web/Desktop 把 `staleTime` 设为无限、关闭 focus 重取、只保留 `refetchOnReconnect`（具体配置表见 [设计模式与策略 §4](设计模式与策略.md#4-缓存策略三层各自有明确的失效源)）。

**为什么**：Multica 是高频协作面板，定时轮询会在多标签/多窗口下放大成本；WS 已能给出确定性补丁。

**代价**：丢事件即数据陈旧，且**离线/断线期间没有任何主动兜底**。移动端因此选择 `staleTime: 60s` + `refetchOnWindowFocus: true` 的不同取舍。

**替代方案（局部采用）**：列表类不确定的变更仍用 invalidate（见 `use-realtime-sync.ts` 的 `refreshMap`）。

## D11 · TypeScript 双编译器并存

**决策**：`pnpm typecheck` 用原生 TS 7（`@typescript/native`）；`typescript` 依赖别名到 TS 6，供 ESLint/Next/仓库脚本使用；`tsc6` 可显式跑旧编译器。

**为什么**：TS 7 尚不能完全替代 TS 6 的编译器 API 消费方。

**代价**：编辑器需要手动指向 `node_modules/@typescript/old/lib`（`CONTRIBUTING.md` 有步骤）；升级 TS 时必须同时更新 `packages/eslint-config/package.json` 的 peer 范围。

## D12 · 依赖版本走 catalog，双工作区声明的依赖必须用 `catalog:`

**决策**：`pnpm-workspace.yaml` 的 `catalog:` 是版本单一来源；两个及以上工作区声明同一依赖必须在 catalog 中。

**为什么**：`scripts/check-dependency-catalog.mjs` 在 CI 上强制，避免同一包在同仓库出现两个版本。

**代价**：升级一般是一次 catalog 改动 + 多处无需改动；例外（mobile 的 Expo 对齐包）在 `AGENTS.md` 里显式豁免。

## D13 · 会话无服务端撤销

**决策**：JWT 仅靠 `exp` 失效；登出只清 cookie，不写撤销表；滑动续期在剩余寿命 ≤ TTL/2 时重签。

**为什么**：避免每次请求查会话表；代价被显式接受（`auth/session.go:14-22` 记载）。

**代价**：令牌泄漏在过期前始终有效；活跃会话可无限延长。相邻风险：PAT 撤销有 10 分钟缓存滞后、成员移除有 5 分钟滞后。

## D14 · 代码注释只用英文，产品文案走统一术语表

**决策**：Go 与 TS 代码注释一律英文（`conventions.mdx` 明说"发现中文注释即视为 bug"）；`issue` 在各语言译为当地"任务"词，`task`（运行）译"运行"；`skill`/状态枚举保留小写英文。

**为什么**：`conventions.mdx` 是 i18n 的单一真源，`packages/views/locales/glossary.md` 已删除并合并进去。

**代价**：任何翻译 PR 都必须对照该页；UI 文案默认不写描述（`AGENTS.md` UI Copy 规则）。
