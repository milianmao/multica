# 设计模式与策略

只记录**项目实际在用**的模式。每条给出权威位置，细节不再重复。

## 1. 统一准入契约（Admission）

每次「显式指定执行目标」的入队（评论 @、自动化手动触发、指派/批量提升、手动重跑、直接 chat）都返回同一形状：

```
queued | coalesced | deferred | steered | blocked + reason_code
```

- 定义：`server/internal/handler/admission.go:20-70`（`DispatchStatus`、`DispatchReasonCode` 别名到 `dispatch` 包）。
- 取值：`server/internal/dispatch/reason.go`（21 个稳定码，含 `invocation_not_allowed`、`runtime_offline`、`issue_in_triage`、`quota_exceeded`）。
- 两条不变量（`admission.go:13-18`）：①「业务对象已写入」与「agent 已触发」是两个不同事实，允许部分成功；②拒绝原因只暴露枚举码，**绝不泄漏目标是否存在/名称/owner**。

→ 数据流详见 [Agent 任务生命周期](../03-核心数据业务流/Agent任务生命周期.md)

## 2. 幂等与去重（多层，各管一段）

| 层 | 机制 | 位置 |
|---|---|---|
| 任务入队 | 唯一索引 `(issue_id, agent_id, COALESCE(comment_thread_id,0)) WHERE status IN ('queued','dispatched')`；冲突映射为 `ErrDuplicatePendingTask` | `migrations/452_agent_task_pending_thread_unique.up.sql:2-5`；`service/task.go:738,1391` |
| 评论合并 | 同一条待处理任务合并新评论，而非新建 | `service/comment.go:2449` |
| Chat 提交 | `submission_id` + SHA-256(content + 排序去重后的 attachment ids) 指纹；同 key 异指纹 → 409 | `service/chat_submission.go:52-71` |
| 频道入站 | 两阶段 `Claim`/`Mark`/`Release` + 60s owner-fence token | `pkg/db/queries/channel.sql:1048-1087`；`integrations/channel/engine/resolvers.go:282` |
| 流式消息 | `idempotency_key → uuid.NewSHA1(taskID, key)` 确定性 ID | `handler/daemon.go:5856` |
| 定时任务 | `sys_cron_executions` 唯一键 `(job_name, scope_kind, scope_id, plan_time)` 充当分布式租约 | `internal/scheduler/spec.go:1-11` |

规则：**幂等键必须由客户端提供且随请求持久化**，服务端不猜。

## 3. 降级策略（每个可选依赖都有显式退化路径）

| 依赖缺失 | 行为 | 位置 |
|---|---|---|
| Redis 未配置 | 实时退化为单进程内存 Hub；限流 no-op；频道租约回落 PostgreSQL | `cmd/server/main.go:594`、`router.go:285-315` |
| 服务端 LLM 未配置 | 辅助层完全惰性：chat 用前 30 字符派生标题，追问建议按钮不出现 | `.env.example` LLM 段 |
| S3 未配置 | 附件落本地 `LOCAL_UPLOAD_DIR` | `.env.example` |
| Resend/SMTP 都缺 | 验证码打印到 stdout | `.env.example` |
| multica-cloud 未配置 | `seatcapacity.New` 返回 nil，`entitlement` 不注入，自托管行为不变 | `handler/seat_capacity.go:29-31`；`entitlement/README.md:80-82` |
| 商店主题源不可达 | 内置主题仍可用 | `docs/theming.md` |

**方向不一致是刻意的**：`entitlement` 故障 fail-open（返回 `ActionOff`），`seatcapacity` fail-closed（`NewUnavailable`）。判断「策略失效时该放行还是拒绝」前先确认在哪一侧。

## 4. 缓存策略（三层，各自有明确的失效源）

| 层 | 策略 | 位置 |
|---|---|---|
| Query 缓存 | `staleTime: Infinity`、`gcTime: 10min`、`refetchOnWindowFocus: false`、`refetchOnReconnect: true`、`retry: 1` | `packages/core/query-client.ts:6-20` |
| 移动端 Query | 独立配置：`staleTime: 60s`、`refetchOnWindowFocus: true`，`focusManager←AppState`、`onlineManager←NetInfo` | `apps/mobile/data/query-client.ts:21-50` |
| 服务端 Redis | relay 流保留期、PAT 缓存（撤销滞后 10min）、成员缓存（移除滞后 5min）、runtime liveness TTL 90s、频道租约 180s | `sharded_stream_relay.go`、`auth/pat_cache.go:17`、`auth/membership_cache.go:19` |

**核心权衡**：Web/Desktop 把新鲜度全押在 WS 上。任何丢事件/重连缺口只能靠 `refetchOnReconnect` 或显式 invalidate 兜底——排查"桌面数据不更新"先看 `use-realtime-sync.ts`。

## 5. 错误处理与状态码约定

| 场景 | 约定 |
|---|---|
| daemon 终态回调 | 业务失败返回 **5xx**；400 被视为永久错误、daemon 直接放弃重试 | `handler/daemon.go:4984-4989` |
| 已终态重复回调 | 幂等成功（`transitioned=false`），不报错 | `service/task.go:4876-4894` |
| 未知枚举值 | 客户端 `switch` 必须有 `default` 分支；未知 reason code 按通用失败处理 | `admission.go:56-60`、`AGENTS.md` API Compatibility |
| 响应解析 | 一律 `parseWithFallback` + zod，**禁止 `as T`** | `packages/core/api/schema.ts:38-58` |
| 旧前端 + 新后端 | 视为常态：服务端新增字段必须有默认值/回退 | `AGENTS.md` API Compatibility |

## 6. 事件驱动（业务事实 → 传输，不耦合）

- 业务侧只 `bus.Publish`；进程内订阅者与 WS 转发者互相独立（`events/bus.go:94`）。
- 传输层可见字段由**声明式表**裁剪，而不是散落的 `if`：`internalOnlyPayloadKeys`（`cmd/server/listeners.go:38`）。新增 payload 大字段必须回来登记。
- 受众由订阅者按序短路决定：个人 → chat 私有 → 成员私有 → 私有项目 → workspace 广播（`listeners.go:129-361`）。

→ 详见 [实时事件广播链路](../03-核心数据业务流/实时事件广播链路.md)

## 7. 特性开关（同一套语义，Go 与 TS 各一份）

- 链式 provider，**从最具体到最通用**：请求级覆盖 → env（`FF_<KEY>`）→ YAML 文件 → 静态默认 → 调用方默认值。
- Go：`server/pkg/featureflag/chain_provider.go`；TS：`packages/core/feature-flags/chain-provider.ts`。
- 百分比分桶哈希在两侧**故意保持一致**并有跨语言黄金测试（`packages/core/feature-flags/hash.test.ts` 钉住与 `server/pkg/featureflag/eval_context_test.go:92` 的相同值）。

## 8. 平台适配（依赖倒置）

共享代码从不直接触达平台 API：`NavigationAdapter`（`packages/views/navigation/types.ts:1`）、`StorageAdapter`（`packages/core/platform/storage.ts`）、`openExternal`（`packages/views/platform/open-external.ts:16`）。平台差异全部在 `apps/*/platform/` 实现。

## 9. 仓库隔离（Checkout 而非 Clone）

daemon 用 `multica repo checkout` 到 task 工作目录，通过 Git worktree 复用共享对象库，并在链接 worktree 里遮蔽共享的 `user`/`author`/`committer` 配置（`CONTRIBUTING.md` "Git Identity in Managed Task Checkouts"）。
