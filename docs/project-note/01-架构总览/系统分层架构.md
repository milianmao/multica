# 系统分层架构

## 一句话定位

Multica 是一个「人 + AI 编码智能体」协作的工作区：Issue 被指派给 agent 后，后端排队产生一次 Run（API/DB 里叫 `task`），由**运行在用户自己机器上的 daemon** 拉起本地 AI CLI 执行，过程与结果通过 WebSocket 实时回流到 Web / Desktop / Mobile。

## 五层结构

```
┌─ 客户端层 ────────────────────────────────────────────────┐
│ apps/web (Next 16)   apps/desktop (Electron+React)        │
│ apps/mobile (Expo/RN)                                     │
└───────────────┬───────────────────────────────────────────┘
                │ HTTPS /api/*  ·  WSS /ws  ·  cookie 或 Bearer
┌───────────────▼───────────────────────────────────────────┐
│ 后端 API (server/cmd/server, Go + chi)                     │
│  handler(164 文件) → service → pkg/db (sqlc 生成)          │
│  realtime hub + Redis relay  · scheduler  · integrations   │
└───────────────┬───────────────────────────────┬───────────┘
                │ SQL (pgx)                     │ WS /api/daemon/ws
┌───────────────▼──────────────┐   ┌────────────▼───────────┐
│ PostgreSQL 17 (pgvector 镜像) │   │ daemon (server/internal/│
│ 680 个迁移，168 张表          │   │ daemon) + pkg/agent     │
└──────────────────────────────┘   └────────────┬───────────┘
                                   子进程：claude / codex / cursor / …
```

## 共享包边界（`AGENTS.md` 强制）

| 层 | 包 | 允许依赖 | 明令禁止 |
|---|---|---|---|
| 无头逻辑 | `packages/core` | 仅自身 | `react-dom`、`@multica/ui`、`next/*`、`process.env`、直接 Web Storage |
| 基础 UI | `packages/ui` | 仅自身 | `@multica/core`、业务逻辑 |
| 共享页面 | `packages/views` | `core` + `ui` | `next/*`、`react-router-dom`、store 定义 |
| Web | `apps/web` | 任意共享包 + `next/*` | 其它 app |
| Desktop | `apps/desktop` | 共享包 + `react-router-dom` + electron | 其它 app |
| Mobile | `apps/mobile` | core 的类型与纯函数（按子路径导入） | web/desktop 的 store、hooks、Query 工厂 |

依赖方向恒为 `views -> core + ui`；core 与 ui 互不依赖。共享包导出原始 TypeScript，由消费方应用编译（`apps/web/next.config.ts:43` 的 `transpilePackages`）。

## 后端内部分层

| 层 | 位置 | 职责 | 证据 |
|---|---|---|---|
| 装配 | `server/cmd/server/main.go`（998 行） | 读 env、建 pgxpool / Redis、装 broadcaster、scheduler、listeners、清理器 | `main.go:498-603`（Redis 与 relay 选择） |
| 路由 | `server/cmd/server/router.go`（2933 行） | 中间件链 + 全部 HTTP 路由 | `router.go:1497-1524`（全局中间件）；`router.go:1799-2700`（workspace 作用域大组） |
| 编排 | `server/cmd/server/*_listeners.go`、`*_sweeper.go` | 事件订阅、后台清扫 | `listeners.go:270`（`bus.SubscribeAll` 转发器）、`runtime_sweeper.go:26` |
| Handler | `server/internal/handler/`（164 个非测试文件） | 入参校验、鉴权、UUID 解析、调用 service | `handler/handler.go:981`（`roleAllowed`）、`handler/actor_guards.go:15` |
| Service | `server/internal/service/` | 业务事务、状态机、幂等 | `service/task.go`（任务生命周期核心） |
| 数据 | `server/pkg/db/queries/*.sql` → `pkg/db/generated/` | sqlc 生成强类型查询 | `server/sqlc.yaml`；`make sqlc` |
| 领域包 | `server/internal/{realtime,daemon,dispatch,scheduler,integrations,entitlement,seatcapacity,projectaccess,skill}` | 横切能力 | 见 `04-服务层与IPC通信.md` |

Handler 层不直接写业务 SQL：workspace 作用域由中间件注入 context（`server/internal/middleware/workspace.go:197-270`），写成前必须 `loadXxxForUser` 解析实体（`AGENTS.md` Backend UUID Rules）。

## Daemon 分层

| 关注点 | 位置 |
|---|---|
| 生命周期/循环 | `server/internal/daemon/daemon.go:2085`（`run`）、`shutdown.go` |
| 领取任务 | `server/internal/daemon/client.go:306`（HTTP claim），`wsrpc.go:315`（WS 优先，HTTP 兜底） |
| 运行时探测 | `agents_probe.go`、`agents_refresh.go`、`pkg/agent/builtin_runtimes.go` |
| Prompt 构造 | `prompt.go`、`task_cli.go`、`slash_skill.go` |
| 执行后端 | `server/pkg/agent/*.go`：每个 CLI 一个 backend，协议族见 `agent.go:412` |
| 产物/环境 | `environments.go`、`localenv/`、`gc*.go`、`artifact_matcher.go` |

`SupportedTypes`（`server/pkg/agent/agent.go:412-442`）列出协议族：claude、codex、cursor、copilot、opencode、kimi、amp、droid、devin、qoder、grok、qwen…；`BuiltinRuntimes`（`builtin_runtimes.go:86`）登记复用其它协议族的身份，目前只有 `omp`（走 `pi` 协议）。

## 典型请求路径（读一条 issue 列表）

1. `apps/web` 页面（薄壳）渲染 `@multica/views` 组件。
2. Query hook 用 `issueKeys.list(wsId)` 发请求（`packages/core/issues/queries.ts:51-59`）。
3. `packages/core/api/client.ts` 附加 `X-Workspace-Slug`（`client.ts:934-935`）与 cookie/CSRF。
4. `router.go` 的 workspace 大组中间件解析 workspace、校验成员身份（`middleware/workspace.go:197-270`）。
5. handler 调 service → sqlc 查询（`workspace_id` 谓词是租户隔离不变量）。
6. 响应经 zod schema 校验后进 TanStack Query 缓存（`parseWithFallback`，`packages/core/api/schema.ts:38-58`）。

## 实时路径（写一条评论的扇出）

`bus.Publish`（`server/internal/events/bus.go:94`）→ 进程内类型处理器 → `SubscribeAll` 转发器按受众分派（`listeners.go:129-361`）→ Hub 本地广播 + Redis sharded relay 跨副本 → 客户端 `WSClient`（`packages/core/api/ws-client.ts`）→ `useRealtimeSync` 打补丁/失效 Query。

→ 数据流细节详见 [实时事件广播链路](../03-核心数据业务流/实时事件广播链路.md)

## 架构约束（红线）

- 前端不跨包重复实现：同一逻辑出现在两个 app 就必须下沉到共享包（`AGENTS.md`）。
- 页面是薄壳：`apps/web/app/[workspaceSlug]/(dashboard)/*/page.tsx` 只做装配，实体在 `@multica/views`。
- 导航必须走 `NavigationAdapter`/`useNavigation()`/`<AppLink>`；整页跳转被 ESLint 拦（`packages/eslint-config/full-page-navigation.js:17`）。
- 客户端 store 只在 core（desktop/mobile 各自平台 store 除外）；`packages/views` 禁止 `zustand` 的 `create`（`packages/views/eslint.config.mjs:19-25`）。
- 服务端数据归 TanStack Query，客户端 UI 状态归 Zustand；两者不得互换（`AGENTS.md` State Rules）。
