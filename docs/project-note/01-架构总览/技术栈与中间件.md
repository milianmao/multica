## 中间件与外部服务（按是否必需分类）

| 能力 | 组件 | 必需性 | 行为 |
|---|---|---|---|
| 主存储 | PostgreSQL | **必需** | 680 个迁移（`server/migrations/`），168 张不同的表 |
| 实时跨副本 | Redis Streams（sharded relay） | 可选 | 未配置时退化为单进程内存 Hub（`main.go:594`） |
| 限流 | Redis | 可选 | 未配置则 fail-open 并打印 "auth rate limiting disabled" |
| 频道租约 | PostgreSQL 或 Redis | 二选一 | `CHANNEL_WS_LEASE_BACKEND`，Redis 不可用时 fail-closed 不建连 |
| 对象存储 | S3 / CloudFront / 本地目录 | 可选 | 未配置 S3 时落 `LOCAL_UPLOAD_DIR=./data/uploads` |
| 邮件 | Resend 或 SMTP | 可选 | 都未配置时验证码打印到 stdout |
| 产品分析 | PostHog | 可选 | key 为空则 no-op client |
| 模型辅助 | OpenAI 兼容网关 | 可选 | 仅两个消费者：chat 自动标题、追问建议；关掉零请求 |
| 托管云 | multica-cloud（`MULTICA_CLOUD_URL`） | 可选 | 驱动 Fleet/Billing/entitlement/seat capacity |
| 遥测 | telemetry.multica.ai | 默认开 | `DO_NOT_TRACK=1` 关闭 |

## 四个易混淆的"LLM 路径"

1. **agent 执行**——daemon 拉起本地 AI CLI，用它自己的凭据。**不经过**服务端 `MULTICA_LLM_*`。
2. **服务端辅助层** `server/pkg/llm`——chat 自动标题、追问建议。`MULTICA_LLM_API_KEY` / `_BASE_URL` 都为空时完全惰性。
3. **Qoder Cloud Agents**——服务端托管运行，需要 `MULTICA_VCS_SECRET_KEY` 加密令牌与 journal。
4. **Connected Apps MCP 网关**——`/api/apps/mcp` 把工作区里的 app 工具暴露给 agent。

## 版本事实

- 应用版本：`apps/web` 与 `apps/desktop` 均为 `0.9.0`（`apps/web/package.json`）；移动端 `0.1.0`；文档站 `0.2.0`。
- 根 `package.json:version` 仍写 `0.2.0`，**不可作为发布版本依据**——以 app 包版本与 `packages/views/whats-new/releases.ts` 的条目为准。
- 仓库当前无 git tag（`git tag --sort=-v:refname` 为空），发布以推送 `vX.Y.Z` tag 触发（`.github/RELEASING.md`）。
