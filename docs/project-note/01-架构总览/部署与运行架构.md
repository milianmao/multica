# 部署与运行架构

## 三种运行形态

| 形态 | 入口 | 数据 | 适用 |
|---|---|---|---|
| 本机开发（main checkout） | `make dev` / `make up` | `.env`，库 `multica`，PG 5432 | 日常开发 |
| 本机开发（worktree） | `make worktree-env && make dev` | `.env.worktree`，库 `multica_<hash>`，端口按路径哈希分配 | 并行特性开发 |
| 自托管 | `docker compose -f docker-compose.selfhost.yml up -d` | 命名卷 `pgdata` / `backend_uploads` | 生产/内网 |

另有两种与前面重叠的部署路径：`make selfhost-build`（从当前 checkout 构建镜像）与 `deploy/helm/multica`（Kubernetes Chart）。

## 端口

| 服务 | 默认 | 说明 |
|---|---|---|
| 后端 API | `8080` | `PORT`；`BACKEND_PORT`/`API_PORT`/`SERVER_PORT` 可覆盖且优先级更高 |
| 前端 Web | `3000` | `FRONTEND_PORT` |
| 文档站 | `4000` | dev 回退值（`apps/web/config/runtime-urls.ts:89-91`） |
| PostgreSQL | `5432` | 所有 checkout 共享同一容器 |
| Desktop renderer | 由 `DESKTOP_RENDERER_PORT` 注入 | electron-vite dev server |
| 指标 | `METRICS_ADDR`（如 `127.0.0.1:9090`） | 默认关闭；开启后仅绑回环 |
| 维护 API | `MAINTENANCE_PORT` | 强制 127.0.0.1，**禁止发布**；见 `docs/maintenance-jobs.md` |

Compose 中后端容器恒听 `8080`，主机端口由 `BACKEND_PORT` 决定，所以改端口不需要重建镜像（`docker-compose.selfhost.yml:60`）。

## 环境变量分组（完整清单以 `.env.example` 为准，776 行）

| 组 | 代表变量 | 备注 |
|---|---|---|
| 数据库 | `DATABASE_URL`、`DATABASE_MAX_CONNS`、`DATABASE_REPLICA_URL` | 副本连接强制 read-only，5 分钟回收；故障回落主库 |
| 必需密钥 | `JWT_SECRET` | auth JWT + daemon JWT + 附件 URL HMAC；生产拒绝默认值；Compose 不设则启动失败 |
| 服务 | `APP_ENV`、`PORT`、`FRONTEND_ORIGIN`、`MULTICA_PUBLIC_URL`、`MULTICA_TRUSTED_PROXIES` | `MULTICA_PUBLIC_URL` 用于生成 autopilot webhook 绝对地址 |
| 运行时宽限 | `MULTICA_RUNTIME_RECONNECT_GRACE`（默认 `3h`） | 低于 150s 被钳制 |
| 服务端 LLM | `MULTICA_LLM_API_KEY/_BASE_URL/_DEFAULT_MODEL/_MAX_RETRIES` | 全空 = 完全禁用 |
| 功能开关 | `MULTICA_FEATURE_FLAGS_FILE`、`FF_<FLAG_KEY>` | YAML 一次读入，env 覆盖是运维 kill-switch |
| Redis/实时 | `REDIS_URL`、`REALTIME_RELAY_MODE`(sharded/dual/legacy)、`REALTIME_RELAY_*` | 集群模式只允许 sharded |
| 频道租约 | `CHANNEL_WS_LEASE_BACKEND`、`CHANNEL_WS_LEASE_*` | 切换需全副本一起；Redis 需 `maxmemory-policy noeviction` |
| 邮件 | `RESEND_API_KEY` / `SMTP_*` | SMTP 优先于 Resend |
| OAuth | `GOOGLE_CLIENT_ID/_SECRET`、`GOOGLE_REDIRECT_URI` | 前端经 `/api/config` 运行时读取，无需重建 Web |
| 存储 | `S3_BUCKET/_REGION`、`AWS_ENDPOINT_URL`、`ATTACHMENT_DOWNLOAD_MODE`、`LOCAL_UPLOAD_DIR` | `COOKIE_DOMAIN` 用于前后端分域名的 CSRF |
| 集成密钥 | `MULTICA_WECOM_/LARK_/DINGTALK_/SLACK_/TELEGRAM_SECRET_KEY` | 各自为空则该集成整体禁用（503） |
| 插件 | `MULTICA_PLUGIN_SECRET_KEY`、`MULTICA_PLUGIN_SURFACE_ORIGIN`、`MULTICA_PLUGIN_DIR` | surface origin 必须与应用/API 源不同 |
| 注册控制 | `ALLOW_SIGNUP`、`ALLOWED_EMAIL_DOMAINS`、`DISABLE_WORKSPACE_CREATION` | 运行时读 `/api/config`，重启生效 |
| 分析/遥测 | `POSTHOG_API_KEY`、`DO_NOT_TRACK`、`ANALYTICS_DISABLED` | |

## 构建产物

`make build` 在 `server/bin/` 产出三个二进制（`Makefile` build 目标）：

| 二进制 | 入口 | 作用 |
|---|---|---|
| `server` | `./cmd/server` | API + WebSocket + 调度器 |
| `multica` | `./cmd/multica` | CLI 与 daemon（同一可执行文件） |
| `migrate` | `./cmd/migrate` | 迁移 up/down，含并发索引清理登记 |

镜像（`Dockerfile`）：多阶段 Go 构建 → `alpine:3.21` 运行层，额外带 `maintenance`、`backfill_task_usage_hourly`、`backfill_codex_usage_cache`，入口 `docker/entrypoint.sh`。
`Dockerfile.web`：Next.js standalone 输出，Node 精确锁定补丁版本（`22.23.4`）。

## 启动顺序（后端进程内，`server/cmd/server/main.go`）

1. 读 env，`dbstartup` 建 pgxpool（含启动重试预算 `MULTICA_DATABASE_STARTUP_TIMEOUT`）。
2. 读 `featureflag` 文件、`signupConfig`。
3. 若 `REDIS_URL` 存在：建共享 client + 选定 relay 模式；失败仅禁用依赖它的特性。
4. 建 Hub、`DualWriteBroadcaster(hub, relay)`、daemonHub。
5. `registerListeners`（业务事件 → WS 转发）。
6. 启动 sweeper / scheduler / seat-capacity worker / telemetry。
7. `http.Server` 监听 `PORT`；`MULTICA_SHUTDOWN_HOLD_DURATION` 决定 SIGTERM 后先等待多久再优雅关闭。

## 数据库迁移

- 文件：`server/migrations/<NNN>_<name>.up.sql` + `.down.sql`，两侧都要有。
- 当前最大版本 `656`，共 680 个 `.up.sql`。
- **每个索引必须 `CREATE [UNIQUE] INDEX CONCURRENTLY`**，且每条并发索引单独一个只含单语句的迁移文件。
- 每个并发索引必须登记到 `server/cmd/migrate/main.go` 的 `concurrentIndexCleanups`（up）与 `concurrentDownIndexCleanups`（down），否则构建中断留下的 INVALID 索引无法自动清理。
- 改 SQL 后跑 `make sqlc`（sqlc v1.31.1），CI 会校验 `server/pkg/db/generated` 无 diff。

## 本地环境管理（`scripts/dev-env.sh`）

```
make up [C=api,web,daemon,desktop]   # 幂等启动；选择任一组件都隐含 api
make status                          # 显示在跑什么，并证明"是你的"
make down                            # 停进程，保留库/profile/slot
make destroy                          # 停 + 删库 + 删 profile/工作区 + 释放 slot
make list / make gc                   # 列出 / 回收过期或目录已消失的环境
make env-exec ARGS="-- <cmd>"        # 在该环境的变量下执行命令
```

三条设计事实：

- 端口、库名、profile **由目录路径哈希分配**并写入 `~/.multica/dev/` 注册表；删注册表后重跑 `make up` 是受支持的恢复手段。
- 没有任何操作会报告"没到达的成功"：`GET /health` 返回 `pid`/`commit`/`started_at`，`make up` 用它证明应答进程就是刚启动的那个。
- `ARGS=--ephemeral` 记录 24h TTL，由下一次 `make up` 或 `make gc` 回收。

## 自托管要点

- Compose 拒绝启动若 `JWT_SECRET` 为空；生产拒绝已知占位值。
- 首次 `make selfhost` 会自动生成随机 `JWT_SECRET`、`POSTGRES_PASSWORD`、`MULTICA_VCS_SECRET_KEY`。
- 反向代理（Caddy/Nginx/Cloudflare）必须设置 `MULTICA_TRUSTED_PROXIES` 与 `RATE_LIMIT_TRUSTED_PROXIES`，否则所有真实用户共用一个限流桶。
- **WeCom 智能机器人要求后端单副本**：出站只有持有该 bot WS 租约的副本能送达（`.env.example` 的 SINGLE-REPLICA CONSTRAINT 段）。

## 验证流水线

| 命令 | 覆盖 |
|---|---|
| `pnpm typecheck` / `pnpm lint` / `pnpm test` | 前端（不含 mobile，`turbo --filter=!@multica/mobile`） |
| `make test` | 先确保库存在并迁移，再 `scripts/test-go.sh --race` |
| `pnpm test:scripts` | `scripts/**/*.test.mjs`（含 CI 路径选择与门禁） |
| `pnpm exec playwright test` | E2E（服务需已运行，`playwright.config.ts` 不自动启服务） |
| `make check` | `scripts/check.sh`：typecheck → TS 单测 → Go 测试 → E2E |
| `pnpm --filter @multica/mobile {typecheck,lint,test}` | 移动端独立流水线（`.github/workflows/mobile-verify.yml`） |
