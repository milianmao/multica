# 组件架构与通信

## 布局骨架（Web 与 Desktop 用同一张卡片）

```
app shell
├─ AppRail            左侧图标栏（web/desktop 共享）
├─ SpacePanel         空间面板（列表列）
├─ AppShellCard       主内容卡片（data-mc="page"）
│   └─ {children}     页面
└─ AppBottomBar       底部条（md 以下隐藏）
```

实现：`packages/views/layout/dashboard-layout.tsx:35-79`。Web 挂载点在 `apps/web/app/[workspaceSlug]/(dashboard)/layout.tsx:21`，`extra` 槽塞入 `SearchCommand`、`WebNotificationBridge`、`FloatingChat`、`StarPrompt`。

Desktop 在同样的卡片外面**再加一层 tab bar**（`components/tab-bar.tsx:516`），内容宿主是 `components/tab-content.tsx:70,88`。

## 通信机制清单

| 机制 | 用途 | 位置 |
|---|---|---|
| React Context | 平台管道（导航、主题、外观同步、app shell 状态） | `views/navigation/context.tsx:14`、`views/layout/app-shell-context.tsx` |
| Props / 插槽 | 平台差异注入（`loadingIndicator`、`extra`、`Drawer` 等） | `dashboard-layout.tsx:20-32` |
| TanStack Query | 服务端数据（唯一来源） | `packages/core/**/queries.ts` |
| Zustand | 客户端 UI 态 | `packages/core/**/*-store.ts` |
| 自定义 DOM 事件 | web 宿主 ↔ 内嵌桥接（`multica:navigate`、`navigation:gesture`） | `apps/web/platform/navigation.tsx:24-52`、`shared/navigation-gestures.ts:1` |
| 事件总线 | 后端进程内 | `server/internal/events/bus.go:94` |
| WebSocket | 服务端 → 客户端实时 | `packages/core/api/ws-client.ts` |
| Electron IPC | renderer ↔ main（preload 桥） | `apps/desktop/src/preload/index.ts:133-478` |

## 导航抽象（唯一的跨平台导航入口）

契约：`packages/views/navigation/types.ts:1-80`

| 成员 | 必需 | 说明 |
|---|---|---|
| `push/replace/back` | ✅ | 导航 |
| `pathname/searchParams/hash` | ✅ | 「我在哪」三元组，用 `currentPath()` 组合 |
| `getShareableUrl` | ✅ | Web: origin+path；Desktop: 所连环境的公开 web URL |
| `openInNewTab` | 可选 | Desktop 专用；`activate:false` = 后台标签 |
| `openIssueInNewWindow`、`openWorkspaceInNewWindow`、`workspacesInOtherWindows` | 可选 | Desktop 窗口级变体 |
| `openInDesktop` | 可选 | Web 专用，交 `multica://` 协议 |
| `prefetch`、`canGoBack`、`forward` | 可选 | 必须用 `prefetch?.()` / `forward?.()` 调用 |

实现：

- Web：`apps/web/platform/navigation.tsx:78-99`（映射 Next 的 `router`）。
- Desktop：`apps/desktop/src/renderer/src/platform/navigation.tsx:188-278`（先做 overlay/跨工作区/pinned 分流，再 `navigateActiveSession`）。
- Mobile：不使用该契约，直接 `expo-router`（`apps/mobile/eslint.config.js:26-31` 禁直连 `@react-navigation/*`）。

使用约束：共享代码用 `useNavigation()`（`context.tsx:76`，无 Provider 直接 throw）；链接用 `<AppLink>`（`app-link.tsx:25`）。**整页跳转被 ESLint 禁止**（`packages/eslint-config/full-page-navigation.js:17-25`），唯一出口是 `openExternal`（`views/platform/open-external.ts:16-38`）。

## 组件分层约定

| 层 | 位置 | 规则 |
|---|---|---|
| 原语 | `packages/ui/components/ui/`（70 个） | 无业务逻辑；图标一律来自 `@multica/ui/icons` |
| 组合页 | `packages/views/<domain>/`（1029 个 `.tsx`） | 消费 core 的 Query/Store，禁止定义 store |
| 页面壳 | `apps/web/app/**/page.tsx` | 只做参数解析与拼装 |
| 平台壳 | `apps/*/platform/`、`apps/*/components/` | 框架 API 只允许出现在这里 |

新增 UI 组件前先检查 `packages/views/common/` 与 `packages/ui/components/ui/` 是否已有等价物；新原语需至少 3 个调用方（`apps/mobile/AGENTS.md` 对移动端有同样的门槛表述）。

## 数据流（一个典型组件）

```
page.tsx（薄壳）
  → <IssueDetail issueId>
      → useQuery(issueKeys.detail(wsId, id))        ← TanStack Query
      → useIssueSelectionStore(sel)                 ← Zustand（UI 态）
      → <CommentComposer> → useMutation(api.createComment)
      → WS `comment:created` → useRealtimeSync 打补丁 → 自动重渲染
```

`chat/message-cache.ts:1-40` 是这类「单入口写入」的范本：身份是 `message.id`，二次写入合并而非追加，缓存中已有的行胜出。新增消息类缓存写入必须走同类单一入口，不要各 handler 各自 append。
