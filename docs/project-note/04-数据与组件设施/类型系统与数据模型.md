# 类型系统与数据模型

## 约定：线上 snake_case，代码内 camelCase

| 边界 | 形态 |
|---|---|
| HTTP / WS JSON | `snake_case`（`workspace_id`、`created_at`） |
| TS 代码内部 | **始终 camelCase**；`api` 客户端在边界转换 |
| Go struct | 字段 PascalCase + `json:"snake_case"` tag |
| DB 列 / 表 | `snake_case`，表名单数（`user`、`workspace`、`agent_runtime`） |

来源：`apps/docs/content/docs/developers/conventions.mdx` 的 TypeScript 与 Database 段。

## 核心枚举（前端权威定义）

```ts
// packages/core/types/issue.ts
export type IssueStatusCategory = "unstarted" | "started" | "done" | "closed";
export type BuiltInIssueStatus =
  | "backlog" | "todo" | "in_progress" | "in_review"
  | "done" | "blocked" | "cancelled";              // 7 个内置键
export type IssueStatus = BuiltInIssueStatus | (string & {});  // 自定义状态键
export type IssuePriority = "urgent" | "high" | "medium" | "low" | "none";
export type IssueAssigneeType = "member" | "agent" | "squad";
```

**状态模型的两层**（`migrations/469` + `492`）：

| 层 | 值 | 语义 |
|---|---|---|
| 存储键 `issue.status` | 7 个内置键 + 自定义键 | 永远是 `issue_status` 目录里的 `key`，不改成 id |
| 生命周期 `category` | `unstarted` / `started` / `done` / `closed` | 决定行为等价类；自定义状态按 category 继承内置行为 |

内置映射：`backlog,todo→unstarted`；`in_progress,in_review,blocked→started`；`done→done`；`cancelled→closed`。Done 不是通向 Closed 的中间态。

其他关键枚举：

| 枚举 | 值 | 位置 |
|---|---|---|
| 工作区角色 | `owner` / `admin` / `member` | `migrations/001_init.up.sql:30`；`types/workspace.ts:1` |
| 任务状态 | `queued` / `dispatched` / `deferred` / `running` / `waiting_local_directory` / `completed` / `failed` / `cancelled` | `migrations/128_comment_routing_escalation.up.sql:6-17` |
| Runtime 状态 | `online` / `offline` | `migrations/004_agent_runtime_loop.up.sql:8` |
| Autopilot | `status(active/paused/archived)`、`execution_mode(create_issue/run_only)`、`concurrency_policy(skip/queue/replace)` | `migrations/042_autopilot.up.sql` |
| Autopilot run | `pending/issue_created/running/skipped/completed/failed` | 同上 |
| 项目可见性 | `workspace` / `private` | `internal/projectaccess/projectaccess.go:25-38` |

## 核心实体关系

```
workspace 1─┬─ member ─ user
            ├─ agent ──┬─ agent_runtime（daemon 注册的运行时）
            │          ├─ agent_skill ─ skill ─ skill_file
            │          └─ agent_mcp_server / agent_env
            ├─ issue ──┬─ comment ─ (reply_to, mentions)
            │          ├─ issue_to_label ─ label
            │          ├─ issue_dependency / parent_issue_id（自引用）
            │          ├─ activity_log
            │          ├─ attachment
            │          ├─ issue_wakeup ─ issue_wakeup_receipt
            │          └─ agent_task_queue（一次 run）─ task_message / task_usage
            ├─ project ─┬─ project_resource / project_member / project_subscriber
            │           └─ issue（project_id 可空）
            ├─ squad ── squad_member（member | agent）
            ├─ autopilot ─┬─ autopilot_trigger
            │             └─ autopilot_run ─ issue / agent_task_queue
            ├─ chat_session ─┬─ chat_message
            │                ├─ chat_submission_receipt（幂等）
            │                └─ chat_draft_restore
            ├─ plugin_identity ── plugin_release ── plugin_installation ── plugin_grant
            └─ channel_installation ── channel_user_binding ── channel_chat_session_binding
```

（完整表清单见 `server/migrations/*.up.sql`，168 张不同的表；`issue_status`、`issue_view`、`issue_property` 为后期追加）

## sqlc 生成的数据层

- 定义：`server/pkg/db/queries/*.sql`（按域分文件：`agent.sql`、`issue.sql`、`task_message.sql`、`channel.sql`…）。
- 生成：`server/pkg/db/generated/`（`make sqlc`，sqlc v1.31.1）。
- 配置：`server/sqlc.yaml`（`emit_json_tags`、`emit_empty_slices`，并对 `issue_wakeup.condition` 覆盖为 `json.RawMessage`）。
- CI：`sqlc-check` 任务校验生成物无 diff 且无未跟踪文件（`.github/workflows/ci.yml:68-95`）。

## 版本兼容注意

`Issue.status_category`、`Issue.status_name`、`Issue.duplicate_of` 等字段在类型上是**可选**的——为兼容旧后端。读它们必须走 helper（`issueStatusCategory()`、`useStatusLabel()`），不要直接读取。
