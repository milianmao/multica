# 自动化调度链路

两条「无需人点按钮就会产生 run」的机制：**Autopilot**（定时/webhook 触发自动化）与 **Issue Wakeup**（等事件/等时间后再跑一次）。

## 触发点

| 机制 | 触发方式 | 前置条件 |
|---|---|---|
| Autopilot 定时 | scheduler tick 命中 cron occurrence | autopilot 为 `active`；trigger `enabled=true` 且 `kind='schedule'` |
| Autopilot webhook | `POST /api/webhooks/autopilots/{token}`（公开，签名即身份） | trigger `kind='webhook'` 且 token 匹配 |
| Autopilot 手动 | UI / CLI `trigger <id>` | 调用者有权限 |
| Wakeup 事件 | 订阅的事件事实落库（含非 HTTP 写入者） | 订阅启用且未过期 |
| Wakeup 时间 | `after_seconds` / `at` / `interval_seconds` / `cron_expression` | 同上 |

## 数据流路径（Autopilot 定时）

```
scheduler.Manager tick（默认 30s，每进程都跑）
  → 每个已注册 JobSpec 计算 due plan
  → tryClaim（db_ops.go）→ INSERT sys_cron_executions
     唯一键 (job_name, scope_kind, scope_id, plan_time)：只有一个副本能赢
  → 赢家执行 AutopilotScheduleDispatchJob（jobs_autopilot.go:89）
     ├─ PlansForScope：从 autopilot_trigger 反推 cron occurrence（UTC，用 DB now）
     ├─ 迟滞窗口 5min：超过则跳过，等下一个 slot
     └─ DispatchAutopilotForPlan（service/autopilot.go:445）
        ├─ 快路径：查 (trigger_id, planned_at) 是否已有 run
        ├─ 部分完成的 run 先修复再重试
        └─ 按 execution_mode：create_issue（建 issue 并 Assign）| run_only（直接跑）
  → 产生的 issue/task 走普通链路 → 见 Agent 任务生命周期
```

## 数据流路径（Issue Wakeup）

```
订阅写入（issue_wakeup 表，migrations/509_issue_wakeup.up.sql:1）
  ↓
事件发生 → SQL 触发器在同一事务写 issue_wakeup_receipt
  （migrations/520_collaboration_wakeup_events.up.sql:40-41，事实名 'task.'||status）
  ↓
条件评估（issue_wakeup_condition.go 只比较平台已存事实：字段值/子任务状态/PR 状态）
  ↓
CreateWakeupTask → 产生一次**普通** run（无第二套生命周期）
  ↓
若已有 pending task：wakeup 合并进该任务而非新建（issue_wakeup_join.go）
```

## 关键节点详解

| 节点 | 文件位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| 分布式租约 | `scheduler/spec.go:1-11`；`db_ops.go`（`tryClaim`） | `sys_cron_executions` 唯一键即锁；执行记录 ID 用 UUIDv7（索引局部性），lease token 用 v4（不可猜时间） | 输家静默 no-op |
| 补跑策略 | `scheduler/spec.go:23-40`（`CatchUpMode`） | `CatchUpLatestOnly`（有 watermark 的任务，如用量汇总）vs `CatchUpEveryPlan`（每个 plan 桶都有业务意义） | 由 JobSpec 声明 |
| 陈旧租约窃取 | `scheduler/db_ops.go` | 租约过期可被其它副本接管 | 必须幂等；有测试 `stale_steal_test.go` |
| cron 计算 | `service/cron.go:23-70` | 用 **DB 时间** 而非 `time.Now()`，避免副本时钟偏差；副本文本编辑器预览复用同一次解析 | 无后续 occurrence 时返回短切片而不是零时间 |
| 幂等 | `service/autopilot.go:461-475` + 部分唯一索引 `uq_autopilot_run_trigger_planned` | 同一 `(trigger, planned_at)` 不产生两个 run | 快路径返回原 run |
| 唤醒事实 | `eventcontract.WakeupTypes`（`pkg/eventcontract/events.go:32-38`） | 只列**有事务性捕获**的事实，不是全部事件总线类型 | 订阅不存在的事实 = 永不触发 |
| 工作流绑定 | `service/issue_wakeup.go` + `docs/engineering/issue-wakeups.md` | 续跑任务的 `workflow_step` 由来源决定（注册任务步骤/issue 状态/父任务绑定） | 不匹配返回 `409 workflow_step_moved`，不重绑 |

## Autopilot 数据模型（`migrations/042_autopilot.up.sql`）

| 表 | 关键字段 |
|---|---|
| `autopilot` | `assignee_id`、`status(active/paused/archived)`、`execution_mode(create_issue/run_only)`、`concurrency_policy(skip/queue/replace)`、`issue_title_template` |
| `autopilot_trigger` | `kind(schedule/webhook/api)`、`cron_expression`、`timezone`、`webhook_token`、`next_run_at`（仅显示用） |
| `autopilot_run` | `status(pending/issue_created/running/skipped/completed/failed)`、`issue_id`、`task_id`、`(trigger_id, planned_at)` 唯一 |

## 异常路径

| 异常类型 | 处理方式 | 用户可见结果 |
|---|---|---|
| 多个副本同时 tick | 唯一键保证只有一个赢 | 无重复 issue/run |
| tick 迟到超过 5 分钟 | 跳过该 occurrence，等下一 slot | 少一次触发（不补） |
| 进程重启 | trigger 从表里重新推导，无内存定时器 | 无丢失（`sys_cron_executions` 保留审计） |
| 部分完成的 autopilot run | 先尝试恢复再重试 | 不产生半成品 |
| 唤醒事件缺 receipt | 不会触发（只订阅有事务捕获的事实） | 需换用受支持的事件类型 |
| 状态被外部改动 | `409 workflow_step_moved`；不自动重绑 | 需显式 rerun |
| 终态 issue（done/closed） | 禁用所有唤醒配置；重新打开也不恢复 | 需重新启用 |
