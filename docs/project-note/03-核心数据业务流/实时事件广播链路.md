# 实时事件广播链路

一条业务事实（如新评论）如何变成所有相关浏览器里的界面更新。

## 触发点

- 任何业务写操作在事务内/后调用 `bus.Publish(events.Event{...})`（`server/internal/events/bus.go:94`）。
- 任务事件统一经封装 `TaskService.publishTaskEvent`（`service/task.go:7648`）。
- **前置条件**：事件必须有明确 workspace；个人事件必须有目标 user；chat 私有事件必须有 session owner（缺则丢弃并告警，绝不降级广播）。

## 数据流路径

```
业务 handler/service
  → bus.Publish(Event{Type, WorkspaceID, Payload, ActorID, ...})
  → ① 进程内类型订阅者（inbox/invitation/member/plugin bridges…）
    同步执行，各自 recover panic（bus.go:94-128）
  → ② SubscribeAll 全局转发器（cmd/server/listeners.go:270）
      ├─ 受众判定（按序短路）
      ├─ projectOutbound 裁剪内部字段（listeners.go:52-72）
      └─ 发布到 Broadcaster
  → ③ DualWriteBroadcaster
      ├─ Hub：本地连接快路径
      └─ Redis sharded relay：XADD 到 ws:relay:shard:<n>
  → ④ 其它副本 XRead → deliverEnvelope → 各自 Hub
  → ⑤ 客户端 WSClient.onmessage → dispatch（ws-client.ts:173-182）
  → ⑥ useRealtimeSync：setQueryData 补丁 或 invalidate（use-realtime-sync.ts:1179-1233）
  → React 重渲染
```

## 关键节点详解

| 节点 | 文件位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| 发布 | `events/bus.go:94` | 同步分发：类型订阅者先于全局订阅者 | 每个订阅者独立 recover，一个 panic 不影响其它 |
| 受众分派 | `cmd/server/listeners.go:129-361` | 个人事件→`SendToUser`；`chat:*`→session owner 单播；成员私有→`workspace_member` 房间；私有项目→逐人；默认→workspace 广播 | 缺 owner/workspace 直接丢弃并 warn，**不降级** |
| 字段裁剪 | `listeners.go:38-72` | 声明式表 `internalOnlyPayloadKeys`：`issue:updated.prev_description/prev_title`、`task:failed.error` | 复制 map 后删键，绝不改写生产者 map |
| 本地扇出 | `realtime/broadcaster.go:41-43` | 房间键 `WorkspaceMemberScopeID = wsID+":"+userID`；连接时自动入组，客户端不能订阅 | 慢客户端被驱逐（有 metrics） |
| 成员校验 | `realtime/membership.go:156-177`、`membership_batch.go:26-40` | 每条写出前批量复核会员身份 | 被移除者连接被关闭并尽力送达 `member:removed` |
| 跨副本 | `realtime/sharded_stream_relay.go:270-337` | 流键 `ws:relay:shard:<n>`，FNV-1a(scopeType\0scopeID)%8 分片；每分片一个 XRead 循环 | Redis 未配置则不启用（退化为单机） |
| 保留/重放 | `sharded_stream_relay.go:313-395` | 读起点 `now - ReplayGrace`（默认 5m）；`XTRIM MINID(now-TrimHorizon)` | **重放要求下游幂等** |
| 客户端连接 | `packages/core/api/ws-client.ts:89-116` | URL 只带 slug 与 client 元信息；token 不入 query——cookie 模式靠 HttpOnly，token 模式在 `onopen` 发首帧 | 首帧鉴权失败即断开 |
| 重连 | `ws-client.ts:17-18,190-207` | 1s 起、30s 上限、±20% jitter、无限重试 | 恢复后触发 `onReconnect` → 全量失效 workspace 查询 |
| 缓存补丁 | `use-realtime-sync.ts:1179-1233` | `onAny` 前缀表 + 具体事件白名单；按 `type.split(":")[0]` 走 100ms debounce 失效 | 细粒度 `setQueryData` 见下 |
| 流式合并 | `use-realtime-sync.ts:156,1693` | `task:message` leading-edge 立即写，其余按 100ms 窗口合并；按 `seq` 去重排序 | 断线重连后靠 refetch 补齐 |

## 两种事件词汇（不要混用）

| 词汇 | 形式 | 用途 | 权威位置 |
|---|---|---|---|
| 传输/协议事件 | `domain:action`，92 个 | Go 进程内总线 + WebSocket 帧 + 前端 `WSEventType` | `server/pkg/protocol/events.go:36`；`packages/core/types/events.ts:12-104` |
| 业务事实契约 | `domain.action_snake`（`task.queued`、`issue.status_changed`） | wakeup 订阅、插件契约 | `server/pkg/eventcontract/events.go:1-56` |

翻译点只有两处，且**没有机械字符串替换**：

1. 插件桥逐条映射，含语义改名 `task:running → task.started`，并从 `issue:updated` 派生 `issue.status_changed`（`service/plugin_event_bridge.go:52-68`）。
2. wakeup 事实由 SQL 触发器 `'task.'||NEW.status` 生成（`migrations/520_collaboration_wakeup_events.up.sql:40-41`）。

## 跨副本模式

| 模式 | 装配 | 何时用 |
|---|---|---|
| `sharded`（默认） | `NewShardedStreamRelay` | 常态；集群模式唯一允许值 |
| `dual` | `NewMirroredRelay(sharded, legacy)` | 迁移期双写 |
| `legacy` | 每 scope 一条流 + XREADGROUP | 回退 |

`REALTIME_RELAY_MODE` 非法值告警并回落 `sharded`（`cmd/server/main.go:112-125`）。

## 异常路径

| 异常类型 | 处理方式 | 用户可见结果 |
|---|---|---|
| Redis 断连 | 本地 Hub 仍工作；跨副本事件延迟/丢失 | 其它副本上的用户看不到更新，直到重连 refetch |
| 慢客户端 | 有界队列 + 驱逐 + metrics 计数 | 该 tab 需重连 |
| 成员被移除 | 关闭连接，尽力送达 `member:removed` | 前端强制离开 workspace |
| 事件缺 workspace/owner | 丢弃 + warn | 该事件不投递（宁可丢也不越权广播） |
| 重放重复投递 | 依赖下游幂等；WeCom claim TTL 必须 > replay grace | 已读回复可能重发（若 TTL 配错） |
| 私有项目事件 | 逐人投递（成员 + owner/admin） | 非成员完全看不到 |
