# 认证、会话与工作区作用域

一次请求如何被识别成「某个工作区的某个成员（或某台机器）」，以及被拒绝时的确切原因。

## 触发点

| 认证方式 | 入口 | 凭证 |
|---|---|---|
| 邮箱验证码 | `POST /auth/send-code`、`POST /auth/verify-code`（`router.go:1594-1595`） | 6 位码，10 分钟过期，同邮箱 60s 限发 |
| Google OAuth | `POST /auth/google`（`router.go:1596`） | 授权码 → userinfo → `findOrCreateUser` |
| 会话 | `Authorization: Bearer <jwt>` 或 `multica_auth` cookie | HTTPS 请求优先 Bearer（`middleware/auth.go:307-319`） |
| Daemon | `/api/daemon/*` | `mdt_`，回退 `mcn_`/`mul_`/JWT（`middleware/daemon_auth.go:118-269`） |
| 插件机器凭证 | `/v1/*` | `mpi_`（安装）/`mpc_`（回调） |
| 签名/凭证即身份 | webhook、signed-download、share-link、plugin surface | 各自签名 |

## 数据流路径（一次已登录写请求）

```
浏览器请求（cookie 或 Bearer）
  → chimw.RequestID → ClientMetadata → RequestLogger → [HTTPMetrics] → Recoverer
  → PluginSurfaceHostBoundary → ContentSecurityPolicy → CORS
  → [/api/* 组] Auth 中间件
      ├─ 前缀分派：mul_ / mdt_ / mat_ / mcn_ / mpi_ / JWT
      ├─ 剥离客户端伪造的 X-Actor-Source / X-Agent-ID / X-Task-ID / X-User-ID
      ├─ CSRF：cookie 认证 + 非安全方法 → 比对 multica_csrf_session(优先) 或 multica_csrf
      └─ 注入 user + 滑动续期（剩余 ≤ TTL/2 时重签，仅安全方法内联）
  → [大组] RequireWorkspaceMember
      ├─ 解析 workspace：task-token 绑定 → 上下文 → X-Workspace-Slug → ?workspace_slug
      │                 → X-Workspace-ID → ?workspace_id
      ├─ 解析失败 404 / 无 ID 400 / 绑定冲突 403 / 缺 X-User-ID 401
      └─ GetMemberByUserAndWorkspace 失败一律 404（不区分"不存在"与"无权限"）
  → [子组] 可选角色门（owner / admin）
  → handler → service → sqlc（每条查询都带 workspace_id 谓词）
  → 响应
```

## 关键节点详解

| 节点 | 文件位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| JWT 签发 | `handler/auth.go:175-197`（`issueJWT`） | HS256，claims `sub`/`email`/`name`/`sid`/`exp`/`iat` | 生产环境拒绝弱 `JWT_SECRET`（`auth/jwt.go:53`） |
| TTL / 续期 | `auth/cookie.go:47,119-131`、`auth/session.go:82,117` | 默认 30 天；剩余 ≤ TTL/2 才续；<60s 被抬升 | 客户端按 TTL/10 复查 |
| CSRF | `auth/cookie.go:21-45,362-388`；校验 `middleware/auth.go:94` | 双提交 cookie：`multica_csrf`（token 绑定）/`multica_csrf_session`（sid 绑定，优先） | 失败 403；前端被拒后重试一次并降级到 token 绑定值（`client.ts:1072-1076`） |
| Workspace 解析 | `middleware/workspace.go:68-96,115-150` | 六个来源按固定优先级；单一真源函数 | 见流程图错误码 |
| 成员校验 | `middleware/workspace.go:243-256` | 任何查询失败统一 404，避免枚举 | 403 仅用于"存在但角色不够" |
| Actor 判定 | `handler/handler.go:891-896` | agent 分支**只信服务端写入的 `X-Actor-Source: task_token`**；header pair 兜底明确不是安全边界 | 未知来源默认等同人类（fail-open） |
| 人类专属端点 | `handler/actor_guards.go:15-37` | `RequireHumanActor` 拒绝 `task_token` 与 `cloud_pat` | 403 |
| 令牌前缀 | `auth/jwt.go:61-83`、`auth/cloud_pat.go:24`、`service/plugin_token.go:36-38` | `mul_` 用户 PAT / `mdt_` daemon / `mat_` agent 任务 / `mcn_` 云节点 / `mpi_` 插件 | 分派在 `middleware/auth.go:110,169,210` |
| 项目访问级别 | `projectaccess/projectaccess.go:25-38,101-171` | `workspace`（全员）/ `private`（项目成员 + owner/admin）；agent run 需发起人与 agent owner 双通过 | 私有项目事件逐人投递 |

## 租户隔离不变量

`server/cmd/server/workspace_scope_guard_test.go:20-32` 守护的是：**每条 scoped 查询的 `workspace_id` 谓词不能被删**。跨 workspace 调用必须退化为 0 行 no-op 或 `pgx.ErrNoRows`，而不是改到别人的行。

→ 相关测试策略详见 [测试策略](../05-项目开发规范/测试策略.md)

## 异常路径

| 异常类型 | 处理方式 | 用户可见结果 |
|---|---|---|
| 未登录 | 401 | 跳登录 |
| 无该工作区成员身份 | 404（不暴露存在性） | 页面 404 |
| 有成员身份但角色不足 | 403 | 明确权限错误 |
| CSRF 缺失/不匹配 | 403（cookie 认证的非安全方法） | 前端重试一次后报错 |
| task-token 企图切换 workspace | 403，每次覆盖前拒绝（`middleware/task_token_workspace.go:44-149`） | agent 无法越界 |
| `X-Actor-Source` 被伪造 | 中间件剥离后注入真实来源 | 无法冒充 |
| PAT 被撤销 | 最长 10 分钟缓存滞后 | 仍可用一小段时间 |
| 成员被移除 | 最长 5 分钟缓存滞后；WS 连接主动关闭 | 短暂滞后后失效 |
| 令牌泄漏 | 无服务端撤销，`exp` 前始终有效（`auth/session.go:14-22`） | 需轮换 `JWT_SECRET` |
