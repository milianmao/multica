# 工作区与成员管理

工作区如何创建、邀请成员、核算席位、接受/撤销、移除成员，以及「私有项目」如何收窄可见性。

## 触发点

| 动作 | 端点 | 前置条件 |
|---|---|---|
| 创建工作区 | `POST /api/workspaces` | 已登录；`DISABLE_WORKSPACE_CREATION` 未开；可选 `WORKSPACE_CREATION_ALLOWED_EMAILS` 白名单 |
| 发邀请 | `POST /api/workspaces/{id}/invitations` | owner/admin 角色；邀请者/工作区/收件人三级限流通过 |
| 接受邀请 | 邀请链接流程 | 邮箱匹配、未过期（默认 7 天）、席位可用 |
| 分享链接加入 | `POST /api/share-links/join` | 链接有效且未撤销 |
| 移除成员 | `DELETE /api/workspaces/{id}/members/{memberId}` | owner/admin；不能移除最后一个 owner |
| 离开工作区 | `POST /api/workspaces/{id}/leave` | 非最后 owner |
| 私有项目授权 | 项目成员端点 | owner/admin 或该项目 member lead |

## 数据流路径（发邀请 + 席位）

```
POST /api/workspaces/{id}/invitations（admin 组）
  → 限流：actor / workspace / recipient 三个闸门（Redis 或进程内存）
  → reserveInvitationCapacity → seatcapacity.ReserveInvitation
       └─ 未配置 MULTICA_CLOUD_URL 时 New() 返回 nil，直接放行
  → 校验通过后才消费全部限流预算（失败只扣 actor 预算）
  → 事务内 CreateInvitation（+ seat capacity 确认）
  → 返回邀请
  ↓
被邀请人接受
  → beginCapacityConsume → （邮件/链接）→ Confirm
  → 插入 member 行（role = admin | member，owner 不可受邀）
  → 会员缓存失效 + 邀请事件
```

## 关键节点详解

| 节点 | 文件位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| 席位预留 | `handler/invitation.go:150-165` → `handler/seat_capacity.go:58` | Cloud 预购席位必须先在邀请阶段占位 | `writeSeatCapacityError` 映射 429/409/409/503（`seat_capacity.go:352-369`） |
| 预算消费顺序 | `handler/invitation.go:161-166` | **先向 Cloud 拿到容量再扣滥用预算** | 持久性容量拒绝只扣 actor 预算；瞬时故障不扣 |
| 接受与确认 | `handler/invitation.go:509,560-573` | `beginCapacityConsume` + `Confirm` | 失败释放 |
| 撤销/拒绝/过期 | `handler/invitation.go:114,324,677` | 释放已占席位 | 幂等 |
| 移除成员 | `handler/workspace.go:744-772` | 校验最后 owner → `revokeAndRemoveMember` → `DisconnectMember` → `settleMemberCapacityRelease` → 缓存失效 → 广播 `member:removed` | 至少保留一个 owner（400） |
| 跨副本串行 | `seatcapacity/workspace_locker.go:64,178` | PG advisory lock 保证同工作区席位变更串行 | 阻塞而非失败 |
| 项目可见性 | `projectaccess/projectaccess.go:25-38` | `workspace` 全员 / `private` 成员+owner/admin；维护者跳过计算 | 无权限统一 404 |
| 角色常量 | `migrations/001_init.up.sql:30`；`packages/core/types/workspace.ts:1` | `owner`/`admin`/`member` | 邀请/分享链接只能给 admin|member |

## 席位与配额的两种方向（不要搞反）

| 子系统 | 未配置/故障时 | 位置 |
|---|---|---|
| `seatcapacity` | **fail-closed**（`NewUnavailable`）——拿不到容量就拒绝邀请 | `seatcapacity/client.go:92-110` |
| `entitlement` | **fail-open**（任何失败归 `ActionOff`）——Cloud 抖动即静默取消 issue/autopilot 上限 | `entitlement/README.md:80-82` |
| 自托管（无 `MULTICA_CLOUD_URL`） | 两者都不注入，行为等同无限制 | `handler/seat_capacity.go:29-31`、`router.go:470-492` |

## 异常路径

| 异常类型 | 处理方式 | 用户可见结果 |
|---|---|---|
| 席位已满/超卖 | 429/409 + 明确错误 | 提示联系管理员扩容 |
| 席位服务暂不可用 | 503 | 可重试 |
| 同一工作区并发邀请 | advisory lock 串行化 | 后到者看到最新席位 |
| 移除最后一个 owner | 400 "workspace must have at least one owner" | 明确错误 |
| 被移除者的活动连接 | `DisconnectMember` 关闭并尽力送达 `member:removed` | 其它端立即退出工作区 |
| 邀请过期 | 7 天后失效 | 需重新邀请 |
| 邮箱不匹配 | 拒绝 | 明确提示 |
